## 2. 核心决策

继续使用现有 HKGAI 和 GPT-SoVITS。先交付一个已授权、固定音色的完整实时链路；多音色、微调训练和多人声纹按独立门禁扩展，不先替换模型或新增数据库。

业务音频经 BFF 进入网关，ASR 确认话轮后交给 HKGAI；LLM 文本增量经过短句切分，逐句送给 GPT-SoVITS；合成的音频分块立即透传 BFF，客户端连续播放。

这里的“实时”明确包含两点：

- 上游尚未完成全部合成时，用户已能听到首段声音；不能仅凭 `streaming_mode` 或 WS 握手称为实时播放。
- GPT-SoVITS 每次仍接收一段已确定的文本，不假定它具有持续追加文本的原生双向接口；文本增量由网关切成适合朗读的语义短句。

## 3. 复刻音色：与 ASR 声纹库分开

ASR 声纹回答“谁在说话”；TTS 音色回答“助手用什么声音回复”。两套授权、资源和 ID 分开，不因识别出某人就自动复刻其声音。

第一阶段采用参考音频复刻：

1. 用户提供有使用授权的干净单人语音和准确逐字稿，建议先准备 5–10 秒；远端当前参考音频检查要求 3–10 秒，实际切片服从模型规则。
2. 审核背景噪声、音乐、削波、参考文本及语言；保存为受控 `voice_id`，首个音色可用业务别名 `assistant_default`。
3. 音色记录绑定参考音频、参考文本、参考语言、模型/权重版本和授权状态；业务端只传 `voice_id`，不传服务器路径。
4. 中文、英语、粤语分别试听验收；参考语音语言与合成目标语言分别设置，不把普通话参考稿标成粤语。
5. 效果不达标时再评估离线微调。训练数据与时长按实际效果确定，不承诺“短录音必然完美复刻”。

GPT-SoVITS 官方提供参考样本复刻、少样本微调和跨语言能力；这是选择这条路线的依据，不是本项目质量承诺。见 [官方说明](https://github.com/RVC-Boss/GPT-SoVITS#features)。

现有测试参考音频仅用于技术联调，不等同于用户目标音色。正式复刻的素材授权尚未在本轮确认。

安全与生命周期：

- TTS 推理可能持续需要参考录音，与 ASR 登记“提取向量后不保存原音频”不同；启用音色前明确参考音频保存与删除期限。
- 计划将新音色资源放入 `/data/voice-stack/voices/profiles/<voice_id>/`，不覆盖已有样例；人员声纹仍在 `/data/voice-stack/data/voiceprints/`。
- 音色目录和参考文本按敏感资源保护；鉴权后才能列出和使用，禁止任意路径/URL和客户端调用上游换权重、设置参考音频、重启接口。
- 撤销音色时同时禁止新请求、处理在途任务、清理参考缓存并执行约定的资源/备份删除策略；不能只删除一个业务 ID。
- 每个话轮固定音色版本；跨话轮切换。不可用时明确报错，不静默换成另一个人的声音。

## 4. TTS 网关与协议（网关代码已实现，远端/BFF仍待验收）

| 接口 | 处理方式 |
|---|---|
| `POST /api/v1/dev/tts` | 补齐线上兼容接口，返回完整 WAV，继续服务旧版回归台；不把它标作实时播放接口 |
| `WS /api/v1/tts/stream` | 新增独立实时 TTS：文本、语言、`voice_id`；回传元信息和二进制 PCM，支持取消 |
| `WS /api/v1/realtime` | 保留现有完整音频 + commit；新客户端通过协议协商选择流式 PCM 输出与音色 |
| 授权音色列表 | 通过 BFF 返回可使用的 ID、名称、语言及状态，不返回模型路径、参考稿或原始参考音频 |

新流协议采用明确的请求/话轮/片段标识和递增序号；发送 `tts.start`、音频块、`tts.end`、完成或取消事件。`tts.start` 声明编码、实际采样率、声道、音色版本；未协商的新格式不能直接替换老客户端预期的 WAV。

关键实现：

- 上游先沿用流式 WAV：当前 GPT-SoVITS 首次发送 WAV 头，随后发送原始采样字节。网关增量解析 RIFF 格式和数据块后输出 PCM16 小端，获取真实采样率；不能假定每个 HTTP chunk 是独立 WAV，也不能写死 44 字节头。
- 兼容的完整 WAV 接口使用非流式输出，或在收集 PCM 后重新封装真实长度的 WAV；不能把流式占位头与数据直接拼接就认定是可解码的完整文件。
- 不把 ASR 输入的 16 kHz 写死为 TTS 输出采样率；由实际输出决定，必要时由有状态重采样器转换到播放设备采样率。
- 使用增量读取；检查固定大块读取造成的额外等待。网络块边界不等于采样边界，必须保留未完整的采样字节。
- LLM 增量接收、短句切分、TTS 工作队列及音频发送相互解耦。按标点优先切分，首句短一些；长度/等待时间作为可调候选，不逐字调用 TTS，不在号码、日期、英文词中间随意截断。
- 队列按短句条数和“文本估算的音频时长”同时设上限（`SENSEVOICE_TTS_QUEUE_SIZE`、`SENSEVOICE_TTS_QUEUE_MAX_SECONDS`）；正在合成的项目在完成前仍占用预算，因此慢客户端会对 LLM 施加背压。GPT-SoVITS 只有合成后才能给出真实音频时长，真实值通过 `tts.end`/指标统计，不能把入队估算当成精确时长；单句仍须先经短句切分，超预算应明确报错。
- 同一 GPT-SoVITS 实例当前有共享参考音频缓存和可变权重状态，首期全链路仅允许一个合成任务同时进入实例；独立 TTS 和完整对话共用门禁。
- 取消或断开时显式关闭阻塞流并等待上游线程结束后再释放门禁；GPT-SoVITS 无逐请求停止能力时继续消费并丢弃晚到数据，避免下一话轮串音。
- 多音色先在同一权重上串行使用参考音频；不同微调权重后续绑定独立受控工作进程。不要在并发会话中调用全局换权重接口。

流式模式需比较而非直接锁最快档：当前远端 1 为句段返回，2/3 为更细粒度流式路径；官方说明同时提示响应速度与质量取舍。先以 1 作质量基线，2 作流式候选，3 作低延迟对照，在目标语言和音色上实测后选定。见 [官方 API 源码](https://github.com/RVC-Boss/GPT-SoVITS/blob/main/api_v2.py)。

接口接受模式参数不等于当前权重组合已通过流式验收；S0 还需记录实际模型版本、参数是否被降级以及首块中是否包含有效采样。

## 5. BFF 与播放器必须同时改造

moautoai 需要新增与 TTS 流对应的票据和 WS 代理模式，保留现有 HTTP 完整音频接口。语音服务 Key 仍只在 BFF；新票据绑定用户、渠道、权限、模式和短有效期，不能只由浏览器自选租户或音色。

客户端统一实现一个流式播放器，独立 TTS 与完整对话复用：

- 用户点击开始时解锁 AudioContext；使用 AudioWorklet 持续消费 PCM，而不是等 Blob 完成后再显示 `<audio>`。
- 先以约 100–200 ms 缓冲作为调优起点，按实测抖动调整；按样本时钟连续排队，避免句间断裂、重复播放和爆音。
- 音频接收、实时播放和可选结果留存分开。合成完成不等于播放完成，收到 `turn.completed` 不得清空尚未播放的数据。
- 服务部署到非 localhost 时，页面使用 HTTPS、代理使用 WSS；AudioWorklet 需要安全上下文。见 [MDN](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorklet)。
- 客户端在收到 `session.ready`、完成参数协商后才发送业务音频/文本。
- 真人实时 ASR 使用持续采集、重采样与小帧发送；当前页面录完后一次性发送整个 Blob，只能算录音回放测试，必须与麦克风直播测试区分。
- TTS 回读评测在独立低优先级任务中完成，不等待回读才开始播放，也不与会话关键路径争抢模型。

取消与打断分层实现（网关完整对话已支持协作取消，BFF/播放器仍待联合验收）：

1. 用户主动停止：客户端立即停止播放、清空该请求缓冲；网关完整对话支持 `cancel → turn.cancelled`，丢弃待合成文本和晚到音频，旧请求不能串入新回复。
2. 当前 GPT-SoVITS 的停止状态是实例级，公开 API 未提供可靠的逐请求取消。关闭连接不等于 GPU 计算已停止；实例释放前保持占用或丢弃剩余输出，不调用全局重启影响其他任务。
3. 自动插话作为后续能力：结合回声消除和在线 VAD 验收，避免把助手自己的播音识别成用户打断。不能在首期宣传全双工可打断已完成。

## 6. 同时收敛已有 ASR 问题

- 时间线：partial/final 使用同一音频采样起点；多话轮累加偏移一致；遇到音频缺口切断或明确标记，不能只推进全局偏移却仍拼接两侧音频。
- 在线处理：新版隔离网关已接入独立 FSMN-VAD 并通过自动收口冒烟；收音和推理分离、生产切换前仍需用目标录音验证缓存上限和过载时 final 不丢失。
- 过载保护：ASR 门禁未取得槽位时返回 `server_busy`；实时 ASR 保留当前缓冲，完整对话恢复未进入 ASR 的原始话轮，避免客户端被迫重新录音。
- 多人映射：只使用已验证的 CAM++ 中心向量与标签对应；缺少中心时不把片段向量下标当作说话人 ID。
- 人员识别：可信租户权限、登记语音质量检查、模型 ID + revision + 预处理版本隔离、阈值校准和未知人员拒识。
- 健康状态：分开报告模型加载、实际调用可用与业务质量验收；不能靠一次静音预热将时间线/说话人/人员识别全部设为 ready。TTS 分开报告完整接口、流式接口和当前音色是否就绪。
- 声纹状态：`speaker_identification_mode=anonymous` 只表示会话内匿名编号；只有声纹管理、加密、BFF 会话密钥均就绪且请求通过租户校验时，才允许声称支持跨会话记名匹配。
- CER/WER：复用两端已有的标点/空白过滤，补齐一致的事件标签、符号、数字/ITN及大小写口径；保留原始文本和严格指标，避免归一化掩盖真实识别错误。
- API 契约：声纹已同时提供 `/voiceprints` 与管理端规划的 `/speakers` 别名；`asr.segment.*` 与当前 `asr.final + segments` 仍由 BFF 做事件兼容映射，不让客户端直接依赖两套互相矛盾的字段。

| S0 基线 | 固定源码/依赖/模型哈希和回滚包；核对 LAN 入站与转发；补齐独立完整 WAV TTS | 旧 ASR、对话契约不回退；故障时可恢复现有在线补丁 |
| S1 实时复刻主线 | 单授权音色、独立 WS TTS、增量 BFF、PCM 播放器 | 合成完成前已经开始播放；同一文本/音色能连续播完；无串音 |
| S2 对话整合 | HKGAI 文本与 TTS 解耦、短句调度、会话音色固定、独立播放器、阶段指标 | 音频输入到复刻音色首播完整通过；取消后无旧音频复活 |
| S3 ASR 新能力 | 句段时间线、匿名说话人、可信声纹库、CER/WER口径统一 | 通过既有 FunASR 方案 P1/P2 的真实样本门禁，再启用相应能力 |
| S4 联合验收 | 三语、连续多轮、多人/噪声、资源占用、回退与权限检查 | 保存可复核结果，按能力逐项上线，不用单个 ready 宣布全部通过 |

S1 不依赖声纹身份识别，可以先让用户听到固定复刻音色。旧版与新版的代码适配必须成套验证；生产更新不能只覆盖本机 `realtime_api.py`。

所有模型、工作进程和音色资源保留在 Windows/WSL `/data/voice-stack`；Mac 仅维护源码和文档。先使用 50001 隔离验证，新增 TTS 适配优先复用现有 9880 内部服务并控制并发；若需另起推理实例，先核对显存，使用回环临时端口，不增加对外入口。

本方案不授权现在修改 `.env`、音色配置、密钥、证书、生产 unit 或防火墙。仓库仅提供隔离验证 unit
模板，安装到目标机前仍需列出准确路径、用途与影响，再单独确认。公共电脑上不顺带升级系统 Python、
Torch 或 GPU 驱动。

## 8. 验收与延迟口径

必须同时验证普通话、英语、粤语，并记录语言、音色/模型版本、流式模式、是否冷启动和并发数。首期用已授权录音与现有检查，不新增测试框架、Benchmark 或大量测试资产；需要集中新增测试时另行确认。

- TTS 首有效音频：从完整待合成短句被网关接收，到首个包含 PCM 样本的输出；WAV 头和 `tts.start` 不算音频。
- 客户端首播：从客户端提交该请求，到首个音频样本开始进入播放器输出；单独记录浏览器缓冲和设备延迟，物理出声需音频回环或人工核验。
- 对话首播：从用户 commit/明确话轮结束，到播放器开始输出回复，包含 ASR、HKGAI 等待、切句、TTS、网络和缓冲。
- 各机器只测本地时钟间隔，通过请求 ID 关联；不能直接相减未同步的机器时间戳。
- 同时报 P50/P95、持续合成实时率、卡顿/欠载次数、句间间隔、取消响应和错误率；总推理耗时短不等于首播快。
- 首轮调优目标暂定：热机单会话 TTS 首播约 1 秒量级，对话收口到首播约 2–3 秒量级；这是预算目标，不是现有实测或验收承诺。未达标时根据分阶段数据调整，不能只减小 chunk 掩盖质量退化。
- 音色用不同于参考稿的句子盲听，分别评价“像不像、可懂度、自然度、稳定性”；CAM++ 相似度和同模型 ASR 回读只能作辅助，不伪造百分比音色评分。
- `tts.end`/`turn.completed` 仅标记生成结束；播放器另报告播放完成。首播必须先于整轮生成完成，取消后旧音频不能恢复。

## 9. 用户素材与最终选择

技术链路可先用既有样例验证；要交付用户指定的复刻音色，还需目标声音的已授权 5–10 秒单人参考录音、准确逐字稿和参考语言。
默认先做一个固定助手音色，优先验收中文，再分别验证英语、粤语；不自动登记其他人的声纹、不自动复刻新来电者，也不在未确认素材授权时训练模型。
